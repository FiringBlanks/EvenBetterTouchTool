# API choices and compatibility limits

EvenBetterTouchTool 2.5 targets macOS 14 or later, Apple Silicon. It was compiled on macOS 26.6.2 with Swift 6.3.2, using Swift 5 language mode. Physical trackpad behavior on a 15-inch M4 MacBook Air remains a manual validation task.

## Contacts and physical distance

The original project's `mt.h` ABI and runtime `dlopen`/`dlsym` approach are retained. `MTDeviceCreateList`, contact frame callbacks, start/stop/unregister, and optional device ID and surface dimension symbols come from **private**, undocumented MultitouchSupport. They can change in a future macOS update. Missing mandatory symbols pause the driver rather than crash the app. This is not Mac App Store software.

The contact structure has normalized position, absolute position, size, and density fields. Neither these fields nor `MTDeviceGetSensorSurfaceDimensions` carry a documented physical unit. Sensor surface dimensions are not used as millimeters. No conversion from these values to millimeters is assumed. Calibration is optional: unmeasured devices use normalized movement × 100, explicitly labeled as percentages of each axis throughout sensitivity, gesture editors, and diagnostics. One action per 1% width does not promise 1 mm. Users can opt into true millimeter intervals by supplying measured active-surface width/height or separately calibrating X and Y with ruler-measured travel. Existing measured calibrations are retained. Threshold numbers stay unchanged when switching units; this is disclosed before opting back into relative mode. Unconfirmed dimensions never count as physical measurements. The wizard uses one finger and pauses custom actions during calibration. Measure the active area, not the metal surround. Repeat on external trackpads; calibration is keyed to the private device ID. A device without a stable ID returns to relative sensitivity after reconnection unless measured again. Device IDs themselves are private and not guaranteed stable across OS changes.

## Physical presses and taps

Three-finger Click → Play/Pause is enabled by default in 2.4.1. Four-finger clicks start unassigned. A listen-only mouse observer correlates a down/up cycle with exactly three or four fresh contacts on the selected trackpad. The action fires on release; normal mouse-button events are never suppressed. This is an additive press action, not an exclusive mouse-click remapper. Another mouse's click can also satisfy the correlation when fingers rest on the trackpad, because public Quartz events do not provide reliable originating-device identity. The contact ABI has no validated press bit; density and size are not treated as Force Touch pressure. The UI states the retained-click behavior.

The recognizer has adjustable button selection, contact age, finger settling, late-contact grace, maximum press duration, movement tolerance, cooldown, and synthesized-event filtering. It rejects drags, stale contacts, extra/replaced fingers after the landing grace, repeated button edges, and cancelled/sleep/settings-change sequences. A small contact landing grace accommodates mouse callbacks preceding the trackpad frame. Foreground changes caused by the native click do not discard an armed press; nonmedia actions still require the expected target app, while media click actions can survive a focus change when the effective mapping is unchanged. Permission loss, settings changes, device changes, and emergency disable invalidate pending presses. On 2026-10-25, the user confirmed three-finger click Play/Pause works with their installed 2.4.0 on the intended Mac; other hardware still needs validation. Existing saved click settings are preserved when defaults change.

Taps have independent duration, drift, swipe-cancellation, landing and release windows, cooldown, delayed click checking, and click exclusion. A triggered swipe or observed physical press always cancels its tap. Default duration is 0.50 s, landing 0.15 s, release 0.20 s, movement 2 units, and swipe cancellation 1.5 units; units are measured mm or percentages of each axis. Small drift below the cancellation threshold is accepted before a swipe action has triggered. Taps also require the native conflict confirmation and a working button observer. Delayed checking remains correlation across two OS streams, not a device-identity guarantee. Existing schemas load without the new optional options blocks. All settings support global/app sensitivity and per-gesture overrides with explicit Save.

Physical trackpad presses, fast down/up, Force Touch, simultaneous mouse use, and end-to-end media delivery remain hardware acceptance tests. No claim is made that synthetic contact tests establish hardware reliability.

## Native conflicts

The raw driver observes contacts; an active Quartz scroll tap filters ordinary continuous page scrolling associated with custom swipes. It does **not** intercept Dock/WindowServer’s private Mission Control, App Exposé, dragging, or other gesture events. There is no claim of selective native suppression. The setup checkboxes are explicit user declarations, not an automatic probe or preference writer. Changes to macOS native preferences after setup are not detected automatically.

For the intended configuration:

| System Settings location | Required setting |
| --- | --- |
| Trackpad → More Gestures → Mission Control | Off for custom up actions; leave enabled for a native pass-through mapping |
| Trackpad → More Gestures → App Exposé | Off for custom down actions; leave enabled for native pass-through |
| Trackpad → More Gestures → Swipe between full-screen applications | Four fingers |
| Trackpad → More Gestures → Swipe between pages | Two fingers only, or Off |
| Trackpad → Point & Click → Look up & data detectors | Off for custom taps |
| Trackpad → Point & Click → Tap to click | Off for the conservative custom tap setup |
| Accessibility → Pointer Control → Trackpad Options | Three-finger dragging Off |
| Keyboard → Keyboard Shortcuts → Mission Control | Enable/verify Mission Control and Application windows |

Four-finger horizontal mappings start as native pass-through: **zero synthetic events**. macOS controls their distance, animation, and availability. Reassigning them requires additionally disabling native “Swipe between full-screen applications” and confirming that change separately. Pass-through on a gesture that has been disabled in System Settings naturally does nothing. Notification Center retains its native two-finger edge gesture; no undocumented opening API is used.

## Actions

- Chrome uses **Command–Option–Left/Right Arrow**, from [Google's official keyboard shortcut documentation](https://support.google.com/chrome/answer/157179?hl=en).
- Finder uses **Control–Shift–Tab / Control–Tab**, from [Apple's tab documentation](https://support.apple.com/en-sg/guide/mac-help/mchla4695cce/mac). An Accessibility check requires at least two tab controls in a tab group belonging to the focused Finder window. Missing/unrecognized AX structure fails closed. This can also reject a valid Finder window on OS versions with a different hierarchy; inspect with diagnostics. No window-switch shortcut is sent. The desktop and single-tab windows are ineligible.
- Media commands post `NSEvent.systemDefined`, subtype 8, with the IOKit `NX_KEYTYPE_PLAY/NEXT/PREVIOUS` codes and paired down/up states. This represents the dedicated media keys, not F8/F7/F9 virtual key events. Constants were checked against the installed SDK's `IOKit/hidsystem/ev_keymap.h`. Delivery and which app owns the active media session remain macOS decisions and need real Apple Music/Spotify/browser tests. No app-specific AppleScript is used.
- Volume uses public Core Audio APIs on the **current default output device**, preferring a writable main volume property and otherwise using supported output channels. Values clamp to 0–1; mute uses the device's mute property. HDMI/USB/aggregate outputs may reject software volume/mute; diagnostics reports that and the app does not fall back to unrelated media-key repeats.
- Mission Control, App Exposé, Show Desktop, and desktop switching read **explicit enabled symbolic keyboard preference entries**. IDs 32/33/36/79/81 are an undocumented preference schema, read-only and best-effort. Absent/unreadable/disabled entries do not cause assumed shortcuts to fire. General allows a user-verified fallback (for example Control–Left/Right) when the OS entry is unavailable. Ensure your fallback is actually enabled and matches your keyboard settings. No system preference is modified.
- Lock Screen sends Control–Command–Q. Screenshot sends Shift–Command–5 and opens macOS's screenshot UI. Application switching sends Command–Tab / Command–Shift–Tab (macOS's recent-app order).
- Open Application launches or activates an installed bundle ID. Activate Application only activates an already running app. An app-specific shortcut only runs while that app has focus. Key codes follow the ANSI virtual keyboard layout; non-US layouts may require choosing different keys.
- Shortcut sequences run once per contact session, sequentially, and cancel on focus/settings changes. Ordinary shortcut actions can repeat by distance. System overview, desktop, mouse, playback, application, and mute actions are deliberately one-shot to avoid animation overlap or unsafe bursts.
- Notification Center is marked unavailable; configure a macOS shortcut and assign the Custom Shortcut action instead.

## Distance semantics and performance

Fingers track by identity. A 40 ms landing window permits staggered contact; after that, finger identity/count changes cancel the session until all fingers lift. A short staggered release can finish a tap. Long gaps, duplicate timestamps/IDs, invalid coordinates, large jumps, diagonal movement, physical mouse down, sleep, focus changes, and settings changes cannot produce deferred actions.

Direction locks to one axis. Continuous actions accumulate signed-axis movement in measured millimeters or relative axis percentages, preserve fractional distance within the direction, and consume all complete intervals in the current frame. Reversal starts distance accumulation at the turning point; sub-interval credit from the previous direction is discarded. Once direction locks, every forward increment counts, including sub-jitter samples at interval boundaries. Jitter is an anchor deadband on reversals, accumulating from the last accepted position. Activation movement counts toward the first interval. There is no auto-repeat, inertia, or timer draining action debt.

For synthetic actions, an exceptional burst above 64 intervals in a frame cancels that contact session, and a 120-action/second executor cap plus optional cooldown discards excess work. Volume is exempt from both synthetic-input limits: its full interval count becomes one Core Audio adjustment. A configured continuous-volume cooldown retains steps until subsequent movement after it ends; stationary frames never drain them. A stale-delivery check still discards frames delayed over 120 ms before main-thread execution rather than replaying old gestures after a long stall. Thus the 10 mm → 10 steps rule holds for normal tracking inside these explicit stability limits, not arbitrary input floods. Media actions are one-shot; volume uses distance-based 2-percentage-point changes by default. Reconnection enumeration runs every three seconds, permission/config checks every two seconds. Idle gesture processing does no repeated actions. Idle CPU consumption has not been measured on physical hardware.

## Signing and deployment

The stable bundle ID is `org.evenbettertouchtool.app`. The app is unsandboxed and locally ad-hoc signed by default. An ad-hoc signature is **not notarization** and does not establish a durable signing identity across changed builds. Use a consistent local Apple Development or Developer ID identity (`make SIGN='…'`) to improve grant continuity. Do not enable hardened runtime/library validation blindly: loading a private framework and posting input needs validation on the deployment target. Public distribution requires a developer to sign and notarize their own release. This build does not pretend to be notarized. Grant the actual installed app permissions; the old daemon's grants do not transfer. Re-add stale entries after an unsigned/ad-hoc rebuild if needed.

Sources for contact ABI investigation: [M5MultitouchSupport's original header](https://github.com/mhuusko5/M5MultitouchSupport/blob/master/M5MultitouchSupport/M5MTDefinesInternal.h), [MultitouchSupport function declarations](https://github.com/machinarii/hypervibe/blob/main/MultitouchSupport.h), and the upstream `mt.h` attribution. [Apple's gestures reference](https://support.apple.com/en-us/102482) describes the user-visible native gestures. These sources inform implementation choices; they are not a macOS compatibility guarantee.

## Saving settings

Settings and start-at-login edits apply only after an explicit Save. Closing gesture popovers, switching sections, exporting saved settings, opening the JSON file, Reset, and Quit do not persist drafts. Gesture Save commits that cell only; the main Save commits other pending settings. Runtime safety pauses during calibration and emergency disable are immediate and temporary. Native OS permission/settings controls are separate user actions; the app does not save consent or calibration until Save. Row switches gate custom actions, preserve per-cell choices, and do not suppress native macOS gestures.

Settings uses AppKit regular activation policy while its window is open, so macOS presents the app’s own main menu and temporary Dock icon. Closing the window restores accessory policy when Menu Bar Only is saved. Foreground changes and Save do not demote an open settings window. This follows [Apple’s activation policy definitions](https://developer.apple.com/documentation/appkit/nsapplication/activationpolicy-swift.enum/regular).

Continuous availability is based on the action and its parameters. A one-shortcut Sequence is executed synchronously and can repeat for each distance interval, including imported legacy mappings; a one-shortcut application-specific action can also repeat when the foreground app matches. Adding a second shortcut makes that sequence single-trigger. Timed multi-step sequences never queue repeats or overlap. The editor explains unavailable repeat modes and offers Customize for This App when a mapping is inherited.

## Scroll interception and keyboard delivery (2.3)

The active `.defaultTap` listens only for scroll-wheel events at the session event tap and may return nil. The mouse-button observer remains listen-only. Contact recognition, filter state, and eligibility run on the driver's serial queue; no OS queries or UI work occur in the filter. Eligibility uses saved mappings, app/profile/row gates, permissions, and the selected device. Changes, emergency pause, sleep/disconnect, and permission revocation clear active state. Normal two-finger input, noncontinuous wheels, and events attributed to a synthesizing process pass through. Watchdogs expire stale correlation and lost momentum ends. A recognized native direction is never selected for suppression. There can be a small leading leak if a scroll arrives before its raw contact frame; a mixed native/custom axis is left untouched until raw direction is known. Concurrent smooth mouse scrolling while fingers rest on the trackpad and OS callback ordering require hardware testing. This does not suppress native WindowServer gestures. If the tap is unavailable, custom swipe execution is paused and reported; taps are independently guarded.

System shortcut events now include explicit modifier-key down/up edges and Fn/NumericPad flags for arrow/navigation keys; function keys retain their Fn flag. Physically held modifiers are preserved, and the whole event list is created before posting to avoid partial allocation leaving a modifier held. Tests inspect actual Quartz events without posting them. A disabled symbolic shortcut does not fall back; an absent entry may use a user-verified saved fallback. Show Desktop needs its own verified key, distinct from App Exposé. The private symbolic-hotkey preference schema remains a compatibility limitation.

## Volume feedback

Core Audio adjustments aggregate a frame's distance steps into one clamped write per exposed output channel. The resulting output values are read back before feedback is shown. An owned nonactivating NSPanel and the app's status item show the percentage; a single rescheduled work item hides them after two seconds without another update. Showing feedback does not activate the app or replace the foreground profile. Unsupported output devices report an error. The 42% Diagnostics preview changes no audio. Apple's Control Center Sound panel has no supported opening/closing API used here; this UI is explicitly the app's own indicator.

References: [Quartz event tap creation](https://developer.apple.com/documentation/coregraphics/cgevent/tapcreate(tap:place:options:eventsofinterest:callback:userinfo:)), [Fn event flag](https://developer.apple.com/documentation/coregraphics/cgeventflags/masksecondaryfn), and [Control Center user controls](https://support.apple.com/guide/mac-help/mchlc9d0e1f2/mac).

## Stable feedback and deliberate-pointer fade (2.5.2)

The volume status item reserves a fixed width while feedback is visible, and the nonactivating panel captures one position for that entire visible session. Subsequent values update the existing hosting view without reanchoring or reopening the window. A 0.20-second fade replaces abrupt dismissal. Only mouse movement or dragging can initiate an early fade, after 24 logical screen points of net displacement from the pointer location at the last volume adjustment. Wobble path length is never accumulated. Local/global monitors exist only while visible, watch only movement/drag events, and return events unchanged. Finger counts, other gesture actions, mouse buttons, keys, scroll/momentum, magnify/rotate, and app activation do not trigger dismissal. A new volume change resets the pointer reference and idle deadline, and invalidates an older fade completion so it cannot hide the revived indicator. The two-second idle deadline remains independent of input activity. Native indicator feasibility is recorded in [the investigation](NATIVE-VOLUME-INDICATOR.md); this release retains the custom panel.

Column swaps copy complete Mapping values in the draft only. An app-specific swap resolves inherited values before exchanging them and removes an override when its resulting value matches the corresponding global cell. Global mappings, other profiles, and row toggles are unchanged. Existing native-conflict gates remain in force; swaps do not change macOS settings. Gesture-only Save remains scoped to one cell; use the main Save to commit a complete pending swap.

## Immediate volume updates and complete action menus (2.5.1)

The volume fill is a SwiftUI capsule whose width reflects the latest actual level directly, with animations disabled in its update transaction. The former native ProgressView interpolation is removed; presentation fade remains separate. Assigned action uses five category submenus for the same full action library on every gesture; the four-finger click has no reduced action set.

## Consolidated settings (2.7)

Setup and Gestures are the only tabs, horizontally centered at the top; Setup is initially selected. Gestures includes all sensitivity fields beneath the grid, using its shared application selector. The sidebar and its app-name header are removed. Permission controls are rendered once, first. Startup, native gesture confirmations, profiles and import/export remain available in Setup. Technical device identifiers, calibration, shortcut fallbacks, diagnostics, raw configuration and recovery are in Advanced. The menu-bar Diagnostics shortcut routes into that section, not a hidden legacy tab. No gesture or persistence behavior changes.

Compact row controls use one small hand button and a blue/gray dot. Hover help and accessibility labels identify finger count and state; visible numeric and On/Off captions are omitted. They still edit the same rowEnabled draft settings. Sensitivity shortcuts use transient navigation targets to scroll within Gestures and never save settings.
